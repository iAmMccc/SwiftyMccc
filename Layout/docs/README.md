# iOS 布局系统系列

本系列围绕 iOS 布局系统展开，通过原理拆解与代码示例，系统梳理 View 是如何在不同尺寸、不同状态下完成布局计算的。内容不追求 API 罗列，而是结合实际开发中常见的疑惑与问题，帮助你建立对布局系统更清晰、可推导的认知。

### 1. 概览：认识 iOS 布局系统

作为系列开篇，本篇从整体视角出发，梳理 iOS 布局系统的发展脉络与核心组成。文章会对 Frame、Auto Layout、Safe Area、Size Class 等常见概念进行统一整理，明确它们各自解决的问题以及在系统中的位置。

通过这一篇，你可以先建立一张“全景图”，知道 iOS 的布局能力是如何逐步演进的，以及后续原理与 Auto Layout 内容分别在整个体系中扮演什么角色。

[👉 查看详情](1.iOS 布局系统：概览.md)

### 2. 原理：布局是如何被算出来的

在理解了整体结构之后，本篇将深入布局的执行过程本身。从视图层级、坐标体系、布局时机入手，完整拆解一次布局计算的生命周期，包括 size 计算、位置确定以及父子视图之间的相互影响。

这部分重点回答的是“系统为什么会这样算”，而不是“我该怎么写代码”。适合在遇到布局异常、尺寸不符合预期、嵌套复杂视图时，用来定位问题根因。

### 3. Auto Layout：约束系统的真实工作方式

最后一篇聚焦 Auto Layout。本篇不会停留在约束语法层面，而是从约束的本质出发，讲清楚约束如何参与布局计算，以及优先级、Content Hugging、Compression Resistance 在系统求解过程中的真实作用。

通过具体示例，你将更容易判断约束冲突的来源，也能在复杂界面中更有把握地设计约束结构，而不是反复试值和调优先级。
