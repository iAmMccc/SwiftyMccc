# AlarmManager

`AlarmManager` 是 **AlarmKit 的核心管理器**，采用 **单例模式**，保证应用中所有闹钟操作统一管理，负责授权、调度、控制、查询和监听闹钟。

它提供了完整的 API 来管理闹钟，包括：

| 分类           | 方法 / 属性                   | 职责                                                         | 生命周期 / 状态关系                          |
| -------------- | ----------------------------- | ------------------------------------------------------------ | -------------------------------------------- |
| **授权管理**   | `authorizationState`          | 查询当前授权状态（未请求/拒绝/允许）                         | 权限状态                                     |
|                | `requestAuthorization()`      | 异步请求系统授权使用闹钟                                     | 权限未请求 → 授权/拒绝                       |
|                | `authorizationUpdates`        | 异步监听授权变化                                             | 权限状态变化时触发                           |
| **调度**       | `schedule(id:configuration:)` | 创建闹钟或倒计时，支持单次/重复/倒计时模式，返回 `Alarm` 实例 | 新建 → Countdown / Scheduled                 |
| **倒计时管理** | `countdown(id:)`              | 对正在提醒的闹钟触发倒计时，相当于贪睡或重复                 | Alerting → Countdown                         |
|                | `pause(id:)`                  | 暂停倒计时，进入 `paused` 状态                               | Countdown → Paused                           |
|                | `resume(id:)`                 | 恢复倒计时，从 `paused` 状态回到 `countdown`                 | Paused → Countdown                           |
| **停止/取消**  | `stop(id:)`                   | 停止闹钟响铃，如果重复闹钟则调度到下一次。如果单次闹钟，就取消。 | Alerting / Countdown → Stopped / Rescheduled |
|                | `cancel(id:)`                 | 永久删除闹钟，无论是否重复                                   | Countdown / Scheduled / Alerting → Deleted   |
| **查询/监听**  | `alarms`                      | 获取当前客户端所有闹钟状态                                   | 所有状态                                     |
|                | `alarmUpdates`                | 异步监听闹钟变化（触发、贪睡、取消等）                       | 所有状态                                     |





## 一、授权

在使用 AlarmKit 之前，**授权** 是开发者必须完成的第一步。
AlarmKit 属于 **系统级闹钟框架**，涉及唤醒设备、锁屏展示、声音播放等敏感行为，因此 Apple 为其设计了独立的权限体系。
未经授权的应用将无法创建或调度任何闹钟。



### 1. 申请授权状态

开发者通过 `requestAuthorization()` 方法发起请求：

```
do {
    let state = try await AlarmManager.shared.requestAuthorization()
    print("当前授权状态：\(state)")
} catch {
    print("请求授权失败：\(error)")
}
```

同时也可以查询当前授权状态：

```
let state = AlarmManager.shared.authorizationState
```

两者返回的授权状态，都返回的枚举类型（该枚举是声明在AlarmManager内）

```
public enum AuthorizationState : Codable, Sendable {
    case notDetermined
    case denied   
    case authorized
}
```

第一次满怀欣喜的调用`requestAuthorization` 请求授权，会收到`Error Domain=com.apple.AlarmKit.Alarm Code=1 (null)"`

这是因为需要在 **info.plist** 中添加授权申请。

### 2. 声明授权权限

授权申请需

| 类型                                  | 值类型 | 说明                                                         |
| ------------------------------------- | ------ | ------------------------------------------------------------ |
| Privacy - Alarm Kit Usage Description | String | 当 App 调用 `AlarmManager.requestAuthorization()` 时，系统会弹出权限对话框，并在其中显示此描述。 |

### 3. 监听授权状态的改变

```swift
Task {
    for await status in AlarmManager.shared.authorizationUpdates {
        switch status {
        case .authorized:
            print("✅ 已获得闹钟权限，可正常创建 Alarm。")
        case .denied:
            print("❌ 用户拒绝闹钟权限，建议引导去系统设置。")
        case .notDetermined:
            print("ℹ️ 权限尚未请求，可触发 requestAuthorization()。")
        @unknown default:
            print("未知状态")
        }
    }
}
```

`AlarmManager.shared.authorizationUpdates` 可以用来监听授权状态的变化。但是只监听 **App 内部触发的授权变化**，如果用户从 **设置 App 手动修改权限**，无法监听到。

> 这点看来作用有限。还是需要查询状态 `AlarmManager.shared.authorizationState`





## 二、调度闹钟 schedule

```swift
public func schedule<Metadata>(id: Alarm.ID, configuration: AlarmManager.AlarmConfiguration<Metadata>) async throws -> Alarm
```

参数说明：

`id`：闹钟唯一标识

`configuration`：闹钟配置（包括倒计时、计划、属性、声音、Intent）

**返回值**：`Alarm` 对象，包含闹钟状态与信息

**设计理念**：

- 支持倒计时模式、计划模式、或两者结合
- 统一接口让开发者无需管理低层调度逻辑
- 与 Live Activity 集成，实现倒计时 UI 与通知的同步



### 1. 闹钟上限

```swift
public enum AlarmError : Error {
    case maximumLimitReached
}
```

调用闹钟数量过多时，会抛出异常`AlarmError.maximumLimitReached` ，有趣的是：并没有指明具体上限是多少。 猜测可能跟当前手机环境有关。理论上正常使用，不用考虑上限问题。





### 2. 闹钟配置 AlarmConfiguration

`AlarmConfiguration` 是 **AlarmKit 的灵魂配置对象**，它定义了一个闹钟的**行为逻辑 + 界面表现 + 用户交互**。

```swift
public struct AlarmConfiguration<Metadata> where Metadata : AlarmMetadata {

    public init(countdownDuration: Alarm.CountdownDuration? = nil,
                schedule: Alarm.Schedule? = nil, 
                attributes: AlarmAttributes<Metadata>, 
                stopIntent: (any LiveActivityIntent)? = nil, 
                secondaryIntent: (any LiveActivityIntent)? = nil, 
                sound: AlertConfiguration.AlertSound = .default
    )

    public static func timer(duration: TimeInterval,
                             attributes: AlarmAttributes<Metadata>, 
                             stopIntent: (any LiveActivityIntent)? = nil, 
                             secondaryIntent: (any LiveActivityIntent)? = nil, 
                             sound: AlertConfiguration.AlertSound = .default
    ) -> AlarmManager.AlarmConfiguration<Metadata>

    public static func alarm(schedule: Alarm.Schedule? = nil, 
                             attributes: AlarmAttributes<Metadata>, 
                             stopIntent: (any LiveActivityIntent)? = nil, 
                             secondaryIntent: (any LiveActivityIntent)? = nil, 
                             sound: AlertConfiguration.AlertSound = .default
    ) -> AlarmManager.AlarmConfiguration<Metadata>
}
```

用来描述一个闹钟的“完整配置”：

| 职责                 | 参数                             | 说明                                                 |
| -------------------- | -------------------------------- | ---------------------------------------------------- |
| **什么时候响**       | `schedule` + `countdownDuration` | 支持一次性/重复/倒计时闹钟                           |
| **怎么响**           | `sound`                          | 铃声文件可自定义，必须在 bundle 中                   |
| **显示什么 UI**      | `attributes`                     | Live Activity 展示信息，包括标题、颜色、倒计时显示等 |
| **提供哪些交互按钮** | `stopIntent` / `secondaryIntent` | 用户操作回调：停止闹钟、贪睡、触发其他逻辑           |

## 三、闹钟控制

### 1. 停止与取消

```swift
public func stop(id: Alarm.ID) throws
public func cancel(id: Alarm.ID) throws
```

- **stop**：停止闹钟，如果是重复闹钟则会继续下一次调度
- **cancel**：删除闹钟，不管是否重复
- 两者区别：stop 保留重复逻辑(如果不重复，等同于cancel)，cancel 彻底移除

### 2. 暂停与恢复

```swift
public func pause(id: Alarm.ID) throws
public func resume(id: Alarm.ID) throws
```

- **pause**：将闹钟倒计时状态置为 paused
- **resume**：恢复倒计时，继续触发剩余时间
- 系统自动计算 fireDate，无需开发者手动调整
- **设计意图**：保证倒计时和系统提醒的一致性，即使中途暂停，fireDate 会动态更新

### 3. 延迟/贪睡

```swift
public func countdown(id: Alarm.ID) throws
```

- 类似于“贪睡”或“重复计时”
- 只有当闹钟处于 alerting 状态才有效
- 便于实现重复提醒或计时器重置逻辑
