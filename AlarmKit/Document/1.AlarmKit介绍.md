# AlarmKit整体介绍

在 iOS 26 中，Apple 首次引入了全新的系统框架 —— **AlarmKit**。
它为开发者提供了一种安全、系统级的方式，来创建、管理和呈现闹钟（Alarm）体验。

过去，开发者往往需要借助 **通知（UNUserNotificationCenter）** 或 **后台任务（BGTaskScheduler）** 来实现类似“定时提醒”或“倒计时”的功能。但这些方案要么依赖用户交互，要么受限于系统调度，缺乏一致的系统体验。
而 **AlarmKit** 的出现，则正式为 iOS 带来了一个统一、可靠、可交互的闹钟体系。



使用 `AlarmKit` 在您的应用中创建自定义闹钟和计时器。 `AlarmKit` 提供了一个管理具有可定制日程和 UI 的闹钟的框架。它支持一次性和重复闹钟，可选择倒计时时长和静音功能。 `AlarmKit` 处理闹钟授权并提供用于模板和小组件呈现的 UI。它支持传统闹钟、计时器或两者，并提供方法来安排、暂停、恢复和取消闹钟。



## 一、核心概览：闹钟生命周期

AlarmKit 以“闹钟（Alarm）生命周期”为核心，围绕 **创建 → 呈现 → 管理 → 交互** 四个阶段，提供了一整套系统级 API。
主要包含以下几个核心类与结构：

| 模块                                     | 类/结构                      | 说明                                                         | 典型作用                                           |
| ---------------------------------------- | ---------------------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| **Alarm 实体层**<br>定义一个“闹钟”是什么 | **`Alarm`**                  | 表示一个具体的闹钟实例，包含触发时间、持续时间、状态与唯一标识符。 | 创建、查询或更新单个闹钟。                         |
|                                          | **`AlarmMetadata`**          | 附加的闹钟上下文信息，如标签、来源、备注等。                 | 提供个性化标识或分组信息。                         |
| **展示与交互层**<br>定义“闹钟如何呈现”   | **`AlarmAttributes`**        | Live Activity 的属性集合，定义闹钟 UI 的视觉与结构。         | 决定闹钟在锁屏、动态岛等处的展示样式。             |
|                                          | **`AlarmPresentation`**      | 定义闹钟的展示模板，包括标题、副标题、图标和布局等。         | 构建不同状态下的视觉模板（倒计时 / 响铃 / 暂停）。 |
|                                          | **`AlarmPresentationState`** | 表示系统自动维护的展示状态，如“scheduled”“countdown”“alerting”等。 | 控制 UI 实时刷新与状态切换。                       |
|                                          | **`AlarmButton`**            | 定义用户可在闹钟界面中点击的交互按钮，如“暂停”“再响一次”等。 | 实现与用户的直接交互。                             |
| **管理与调度层**<br>定义“闹钟如何运作”   | **`AlarmManager`**           | AlarmKit 的核心管理器，负责闹钟的调度、授权与生命周期管理。  | 创建、移除闹钟，监听状态变化。                     |

在本系列文档中，将按照这样结构安排章节：

1. **闹钟的定义（Alarm & Metadata）**
   定义一个“闹钟实体”。
2. **闹钟的展示与交互（Attributes / Presentation / Button / State）**
   定义一个“闹钟如何被看到和操作”。
3. **闹钟的生命周期管理（AlarmManager）**
   定义一个“闹钟如何被系统调度和控制”。



## 二、闹钟的状态

| 状态         | 含义 / 执行逻辑                                    | 转换条件 / 下一状态                                | 前台 UI             | 后台未锁屏 UI    | 锁屏 UI        |
| ------------ | -------------------------------------------------- | -------------------------------------------------- | ------------------- | ---------------- | -------------- |
| `.scheduled` | 闹钟已注册，但尚未开始倒计时（静默等待）           | 到达触发时间 → `.countdown`                        | 可自定义显示或无 UI | 无显示           | 无显示         |
| `.countdown` | 倒计时中，等待触发，可被用户暂停（进入 `.paused`） | 倒计时结束 → `.alerting`                           | 倒计时 UI           | 灵动岛倒计时     | 锁屏倒计时     |
| `.paused`    | 用户暂停倒计时                                     | 用户恢复 → `.countdown`                            | 倒计时暂停显示      | 灵动岛倒计时暂停 | 锁屏倒计时暂停 |
| `.alerting`  | 响铃状态，系统播放声音/弹窗提醒                    | 用户停止 → `.scheduled` 或用户 snooze → `.snoozed` | 响铃 UI             | 灵动岛响铃       | 全屏响铃       |
| `.snoozed`   | 用户选择稍后提醒，postAlert 倒计时中               | postAlert 倒计时结束 → `.alerting`                 | 倒计时 UI           | 灵动岛倒计时     | 锁屏倒计时     |

`.paused` 是倒计时中用户主动暂停的状态，是 `.countdown` 的子状态。

`.snoozed` 是 alerting 后的延迟提醒，postAlert 倒计时完成后回到 `.alerting`。








##  四、闹钟的类型

**核心思想**：所有闹钟本质都是倒计时，只是计算倒计时的起点不同。

**倒计时机制**

- 所有闹钟在系统内部都是倒计时触发的。
- 倒计时开始点 = **触发时间 - 当前时间**。

**倒计时起点来源**

- **一次性闹钟**：倒计时起点 = 当前时间到单次触发时间的间隔。
- **重复闹钟**：倒计时起点 = 当前时间到下一次循环触发时间的间隔。

**立即启动的倒计时闹钟（Timer）**

- 倒计时起点 = 当前时间（立即开始），倒计时长度由开发者指定。



## 五、闹钟状态与 Live Activity / Widget UI 呈现

AlarmKit 不仅负责闹钟的调度，还能将闹钟状态与 **Live Activity** 和 **Widget UI** 关联，实现实时、可视化的展示。为了让开发者理解谁负责什么，我们可以按状态分开说明：

### 状态与 UI 责任划分

| 闹钟状态               | 系统自动处理                       | 开发者需要做                                                 | Live Activity / Widget UI 作用                               |
| ---------------------- | ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `.alerting`            | 响铃、震动、通知弹窗、锁屏全屏展示 | 可选自定义前台 App 界面（非必须）                            | 系统可自动刷新到 Live Activity / Widget，显示响铃状态        |
| `.countdown`           | 维护倒计时逻辑和状态更新           | 前台 App 内实现倒计时 UI；配置 `AlarmAttributes` 来呈现倒计时 | 如果配置了 Live Activity / Widget，系统会在灵动岛或锁屏显示倒计时；否则用户不可见 |
| `.paused` / `.snoozed` | 系统维护状态切换和 postAlert 计时  | 可选自定义暂停 UI                                            | Live Activity / Widget 可显示倒计时或暂停状态，需开发者定义  |

**系统管理**：闹钟状态切换、响铃、postAlert、通知、锁屏展示。

**开发者管理**：Live Activity / Widget 内容、前台 App 倒计时 UI、按钮交互和样式。

**Live Activity / Widget** 是连接系统状态与开发者自定义 UI 的桥梁：系统只负责更新状态，开发者定义如何呈现。

### 开发者职责总结

1. **命名与配置 UI**
   - 通过 `AlarmAttributes` 定义 Live Activity / Widget 展示的内容、颜色、按钮、倒计时样式等。
   - 可以给每个闹钟配置独立的属性，使多个闹钟同时显示时区分开。
2. **管理前台 App UI**
   - `.countdown` 状态下，前台 App 需要自行展示倒计时界面。
   - `.paused` / `.snoozed` 状态下，可以展示暂停或稍后提醒的提示。
3. **可选扩展**
   - 自定义按钮交互 (`AlarmButton`)。
   - 前台 App 自定义视觉效果（比如动画、倒计时进度条）。
