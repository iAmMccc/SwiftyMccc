# AlarmPresentationState

`AlarmPresentationState` 描述了某个闹钟在展示层面的“运行/展示阶段”，用于驱动 UI（Widget / Live Activity / App 内组件）在不同展示阶段呈现合适的界面。**此状态由系统自动维护和切换**，开发者只需监听并根据状态更新 UI，而不需要（也不应）自行修改该状态值

```swift
public struct AlarmPresentationState : Codable, Sendable, Hashable {


    /// The unique ID of the alarm.
    public var alarmID: Alarm.ID

    /// The specific state of the alarm, either alerting, countdown, or paused.
    ///
    /// Use `mode` to determine which mode the alarm is in, so that a
    /// widget extension can produce the appropriate UI.
    public var mode: AlarmPresentationState.Mode
}
```



# AlarmPresentationState.Mode 状态模式

这个枚举定义了闹钟主要的三种状态，每个状态携带对应的详细信息（关联数据结构）：

- `.alert`：闹钟响铃通知用户
- `.countdown`：倒计时过程中，可暂停或继续
- `.paused`：暂停状态，倒计时暂停等待恢复

```swift
public enum Mode : Codable, Equatable, Sendable, Hashable {
    case alert(AlarmPresentationState.Mode.Alert)
    case countdown(AlarmPresentationState.Mode.Countdown)
    case paused(AlarmPresentationState.Mode.Paused)
}
```



### Alert（提醒状态）

闹钟已触发并在提醒/响铃（或刚触发，处于 alerting 阶段）。UI 通常展示响铃界面、打断式通知或醒目的交互控件（如停止、延迟等按钮）。

```swift
public struct Alert : Codable, Equatable, Sendable, Hashable {
    public var time: Alarm.Schedule.Relative.Time
}
```

**理解：**  

- **为什么用相对时间？**
  它避免了依赖设备的绝对时间（可能被时区或系统时间变化影响），更适合倒计时场景：比如闹钟刚触发，`time` 是距离触发的秒数（比如 `0` 或 `用时过的秒数`）。
- **如果是绝对时间**：
  表示具体的日期时间（如：2025年10月21日 07:30），但在 `Alert` 内用相对时间可以更加灵活，自容于倒计时等动态调整。

### Countdown（倒计时状态）

闹钟正在进行一个倒计时（例如用户设置了一个 25 分钟的倒计时）；在这个状态可以被暂停与恢复。

```swift
public struct Countdown : Codable, Equatable, Sendable, Hashable {
    public var totalCountdownDuration: TimeInterval
    public var previouslyElapsedDuration: TimeInterval
    public var startDate: Date
    public var fireDate: Date
}
```

| 属性                        | 类型           | 说明                                                         | 用途                      |
| :-------------------------- | :------------- | :----------------------------------------------------------- | ------------------------- |
| `totalCountdownDuration`    | `TimeInterval` | 总时长（秒），用户预设的倒计时长度                           | 总时长，用于比例显示      |
| `previouslyElapsedDuration` | `TimeInterval` | 到最近一次暂停或恢复前，已过去的时间                         | 已消耗时间，用于暂停/恢复 |
| `startDate`                 | `Date`         | 倒计时开始时间（或最近一次恢复的时间）                       | 当前活动段开始时间        |
| `fireDate`                  | `Date`         | 是 **系统在创建或更新闹钟状态时自动计算好的字段**，代表倒计时预计完成的**绝对时间点** | 倒计时完成的绝对时间点    |

- `startDate` 和 `fireDate` 结合表示倒计时的具体时刻。
- `previouslyElapsedDuration` 支持在暂停和恢复时，正确计算剩余时间。

### Paused（暂停状态）

倒计时被用户暂停，计时器不递增，等待用户恢复或取消。

```swift
public struct Paused : Codable, Equatable, Sendable, Hashable {
    public var totalCountdownDuration: TimeInterval
    public var previouslyElapsedDuration: TimeInterval
}
```

| 属性                        | 类型           | 说明                         |
| :-------------------------- | :------------- | :--------------------------- |
| `totalCountdownDuration`    | `TimeInterval` | 原始设置的倒计时总时长       |
| `previouslyElapsedDuration` | `TimeInterval` | 从开始到暂停时累计过去的时间 |



## 状态管理 

`AlarmPresentationState` **不需要开发者自行管理**。该状态由 **系统自动维护和切换**，开发者只需通过监听 `AlarmPresentationState` 的变化来更新界面。

它的作用是反映当前闹钟的展示阶段（例如正在提醒、倒计时中、已暂停等），从而让开发者在不同状态下更新对应的 UI。
在实现中，系统会根据闹钟生命周期自动推送状态变化，开发者无需显式更改 `AlarmPresentationState` 值，只需在 Activity 的内容状态（`ActivityContent.state`）监听或响应这些变化即可。

```swift
struct AlarmWidget: Widget {
    var body: some WidgetConfiguration {
        ActivityConfiguration(for: AlarmAttributes.self) { context in
            switch context.state.presentationState {
            case .alerting:
                AlarmAlertingView(context: context)
            case .countdown:
                AlarmCountdownView(context: context)
            case .paused:
                AlarmPausedView(context: context)
            default:
                EmptyView()
            }
        }
    }
}
```

* 它在 AlarmKit 中是连接系统调度与自定义界面逻辑的关键桥梁。
* 开发者通过监听该状态变化来**调整 UI 呈现**，而不是主动修改它。



## 案例说明：暂停后的倒计时与 `fireDate` 更新机制

在闹钟的生命周期中，`fireDate` 表示**预计的提醒触发时间点**。
在闹钟启动时，系统会根据 `startDate + remainingDuration` 计算出初始的 `fireDate`。
然而，当用户在倒计时过程中**执行暂停或恢复操作**时，这个时间点将不再固定，而是会随状态变化自动调整。

### 示例场景

假设当前时间为 **10:00**，用户设置了一个在 **11:00** 响铃的闹钟，并启用了 **提前 60 秒** 的倒计时。

| 时间     | 事件       | 描述                                                         |
| -------- | ---------- | ------------------------------------------------------------ |
| 10:59:00 | 倒计时开始 | `remainingDuration = 60s`，系统计算 `fireDate = 11:00:00`    |
| 10:59:20 | 用户暂停   | 用户暂停了1分钟时间，此时倒计时已执行 20 秒，剩余 40 秒      |
| 11:00:20 | 用户恢复   | 系统重新计算 `fireDate = 当前时间 + remainingDuration = 11:01:00` |

此时，尽管最初设定的提醒时间是 **11:00**，但由于用户在倒计时过程中暂停了 60 秒，系统会自动将 `fireDate` 延后，保证倒计时仍能准确执行完毕后再触发提醒。
